# 図鑑ノートの書き方（定期作業とClaude向けの決めごと）

このファイルは公開されません（名前が「_」で始まるファイルは build.py が読み飛ばす）。観測所の「観測ノート」（ashitano-tenki/ashitano-tenki.github.io の notes/_guide.md）を図鑑に合わせて写したものです。

## 何を書くか

- テーマごとに、コミュニティ図鑑に載っている公開事例を3〜6件選んで読み比べ、担当者が自社で考えるときの手がかりをまとめる記事。
- テーマは notes/_themes.md の「未着手」から上の順に選ぶ。定期作業（毎日。2026-11-08 から）は書いたらそのまま公開し、「公開済み（日付）」に変える（2026-11-05 黒田さん：ノーチェックで公開してよい、直しはあとから伝える）。
- 長さは本文2,000〜4,000字。です・ます調。

## 記事の流れ

1. 導入：どんなコミュニティの話か、図鑑にその事例が何件あるか（2〜3段落）。件数は「この記事を書いた時点で」と添える。
2. 「始める前に決めておきたいこと」などの見出しで、事例を読み比べて見えた迷いやすい点を箇条書きで3〜4個。
3. 事例の紹介：見出しで分け、各見出しに説明1段落＋ :::case を1〜2件。:::case のあとに、その事例の中身（施策・成果・運営体制）を1段落で補ってよい。
4. 「次の一歩」：事例一覧の検索（/?q=言葉）や絞り込み（/?purpose=目的）、組み合わせのページ（/combos/）へのリンク。

記事の上には、紹介する事例を並べた表（段階・場・規模・工夫のポイント）が自動で入る。表と同じことを本文でくり返さない。

## ファイルの形

notes/<英小文字とハイフンのスラッグ>.md

```
---
title: 記事タイトル（検索されそうな言葉を入れる。40字前後まで。「。」「、」で区切ると画像と見出しの改行がきれいになる）
description: 120字前後の説明（検索結果と一覧のカードに出る）
kind: 社内（社内／ファン・顧客／多企業／社内・ファン など。冒頭と画像の札に出る。多企業は 2026-11-06 に足した種別）
emoji: 1f44b（Noto Emoji のコードポイント。assets/emoji/<コード>.png がなければ足す）
published: 2026-11-12
updated:
draft: false
---
本文。## 見出し、### 小見出し、空行で段落、「- 」で箇条書き、[文字](URL) でリンク、**強調**。

:::case S75
黒田のひとこと（1〜3文）
:::
```

- 絵文字は記事のテーマに合うものを選ぶ。新しい絵文字を使うときは、googlefonts/noto-emoji の 2D/png/128/emoji_u<コード>.png を assets/emoji/<コード>.png として足してコミットする（記事の冒頭に使う）。画像（1200×630）は Actions が 512px の絵文字で作るので、画像のコミットは要らない。
- 画像を手元で確かめるときは `.venv/bin/python tools/make_og.py --notes` で og-items/note-<スラッグ>.png を作って開く。題名が右上の円や下の署名に重なっていないかを見る。
- 公開するときは published に日付（2026-11-12 の形）、draft を false にする。直したときは updated に日付。

## 守ること

- 紹介する事例は、掲載中（https://community-zukan.github.io/data.json の cases にある ID）のものだけ。
- 事例の中身は、公開データの列（主な施策・公開されている成果・運営体制・工夫のポイント・規模・開始年・ツールなど）に書いてあることだけを根拠にする。書いていないことを足さない。数字には、データにある時点（「2025年11月時点」など）を添える。
- 「自社でやるならのヒント（AI生成）」の列は、事実として使わない。
- 各社の取り組みを評価したり、順位をつけたりしない（「いちばん」「おすすめのランキング」などは書かない）。「黒田のひとこと」は、その事例から何が学べるか、どんな会社の参考になるかを書く。
- 迷いやすい点は、事例の傾向（目的・段階・工夫）から言えることだけを書く。知識コレクション（Googleドライブのフォルダ 18NqhI8RhevOEjlamU-C2VjrExAXly-xt）に合う話があれば、出典のある事実だけを短く使ってよい。会議の記録（notta log）など、個人の会話をもとにしたものは使わない。
- 「多くの企業が」「増えている」と一般化しない。図鑑の件数で言えることは「図鑑には○件あり」と書く。
- 黒田さんが関わっている事例（ReFa COMMUNITY、Sansan User Forum）も、ほかと同じに扱う。注記はしない。
- 「3つの場（現場・修羅場・酒場）」という枠組みは使わない。
- 黒田さん自身の経験は、確かなもの以外は作らない。
- 出典の文章をそのまま写さない。図鑑の要約をもとに、自分の言葉で書く。
- AIっぽい言い回し（比喩動詞、「〜の本質」「重要なのは」、コピー調の体言止め、絵文字、過剰な太字）を避ける。yomiyasu スキルの方針に従う。
